# Live Ops Essentials — Cadence, Events, Updates

Live-ops is everything that happens after launch: content cadence,
major updates, quality-of-life improvements, and bug fixes. The goal
is to keep existing players engaged (retention) and re-engage lapsed
players (reactivation).

## The four live-ops activities

1. **Content cadence** — regular small content drops
2. **Major updates** — new gameplay systems, expansions
3. **Quality-of-life** — UI, UX, accessibility, perf polish
4. **Bug fixes** — severity/impact/effort triage

## Content cadence frequency

Successful Roblox games release on a **weekly to monthly** cadence:

| Cadence | Content type | Typical work budget |
|---------|--------------|---------------------|
| Weekly | New cosmetic, shop rotation, event rewards | 1–3 days |
| Bi-weekly | New mission, small event, quest pack | 1 week |
| Monthly | New map, minor gameplay addition, theme drop | 2–3 weeks |
| Quarterly | Major update, new mechanic, expansion | 1–3 months |
| Seasonal | 4–6 large events/year | Varies |

Rule of thumb: **keep individual content drops under three weeks** of
effort so that the cadence is sustainable. Anything longer goes into
the Major Updates track.

## Content types

- **Limited-time events** — temporary, scarcity drives engagement
- **Seasonal content** — returning annually, holiday themes
- **User-generated content** — contests, featured builds
- **Cosmetic drops** — skins, pets, particles, emotes
- **Time-limited modes** — new game modes that rotate

## Major update types

- **Social systems**: guilds, trading, parties, co-op
- **Competitive systems**: PvP, leaderboards, tournaments, ranked
- **Collections**: pet systems, season passes, achievements
- **Live events**: large time-limited, cross-game, expansion-flavored

## Best practices (from Roblox docs)

1. **Listen to players** via Discord, community groups, DevForum.
2. **Connect updates to the core loop.** Every drop should serve what
   players are already doing — not pivot them into a new game.
3. **Analyze player data**: use the analytics dashboard and custom
   events to see where players drop off, what they buy, what they
   ignore.
4. **Prioritize team mental health.** Burnout-driven crunch shortens
   the life of a live game. Ship less, ship sustainably.

## Concrete Numbers / Examples

- **Content drop max effort**: 3 weeks per cycle
- **Cadence**: weekly → monthly, depending on team size
- **Seasonal events**: 4–6 per year is a normal high-end
- **Quarterly major updates**: 2–3 months of work
- **Daily reward cycles**: 7–14 days with escalating value

## Sample content calendar (12-month)

| Month | Type | Notes |
|-------|------|-------|
| Jan | New Year event + map | Themed cosmetics, new quest |
| Feb | QoL patch | Address top community complaints |
| Mar | Spring event + pet | Seasonal cosmetics |
| Apr | Minor system add | E.g. new vehicle class |
| May | Live event | Cross-server global goal |
| Jun | Summer event + bundle | Big flagship event of the year |
| Jul | Cosmetic rotation | Keep engagement while team builds Q3 |
| Aug | Major update | New map, new mechanic |
| Sep | Back-to-school / fall | Themed cosmetics |
| Oct | Halloween event | Returning annual |
| Nov | Black Friday bundle | Biggest monetization week of year |
| Dec | Winter / holiday event | Second biggest monetization week |

## Communicating updates

- **Announce before launch** — build anticipation
- **Publish patch notes** on Discord, DevForum, in-game news board
- **Maintain predictable schedules** — players plan around them
- **Acknowledge delays publicly** — silence damages trust
- **Collect feedback publicly** — bugs, requests, reactions
